# 图派主页面视觉改版提案

> 版本：2026-11-17  
> 范围：首页、创作台、资产库、社区四个主页面  
> 产出：高保真页面概念图 + 设计说明 + 生图提示词

## 1. 项目理解

图派不是“滤镜库”，也不是“模型站”。它服务的是拍照不自信、但仍想稳定发布生活内容的普通人：用户上传一张日常照片，或只说一句话，系统理解画面、优化提示词并推荐相近模板，随后生成一张愿意发布的作品。原图默认私密，结果图带 AI 标识，满意的配方还能导出成可复用的 Skills。

产品闭环是：

1. 图片 / 文字 / 链接进入；
2. 自动优化提示词；
3. 相似模板与 Skills 预览；
4. 微调模型、画幅和提示词；
5. 异步生成；
6. 修前修后对比、下载、存配方、发布社区。

四页分别承担四种任务：

| 页面 | 用户此刻的问题 | 页面应给出的答案 |
|---|---|---|
| 首页 | “我的照片也能变好吗？” | 先给效果信心，再给最低门槛的第一步 |
| 创作台 | “我要怎么把它做出来？” | 把上传、识别、选方向、生成、带走连成一条清楚的路 |
| 资产库 | “我做过的照片和配方在哪？” | 让资产像私人摄影档案，可检索、可再创作、可成册 |
| 社区 | “别人怎么做，我能不能也做？” | 用作品、配方和 fork 谱系激发参与，同时守住原图隐私 |

## 2. 当前页面的主要视觉问题

- 首页的价值主张清楚，但首屏几乎全是文字，模板区才是最强视觉资产却没有进入第一视线。
- 四个页面共用同一套基础组件，层级主要靠字号和边框，缺少摄影杂志式的节奏与收束。
- 创作台真实流程较长，但初始页只有一张大空卡；准备态、结果态又回到普通后台布局。
- 资产库与社区的空态占据整屏，没有把“作品会如何被呈现”提前展示出来。
- 整体暖灰底与陶土橙方向正确，但缺乏第二种稳定的视觉语言：图片尺度、序号、留白和编辑标注。

## 3. 视觉方向

### 3.1 概念

**独立摄影杂志 + 安静的 AI 暗房。**

首页和社区强调“作品值得被看见”，用大图、版面留白、纸张边缘和小号编辑标注建立审美信任；创作台和资产库强调“事情能做成”，用明确的分栏、步骤和参数卡降低不确定感。AI 不作为漂浮粒子或霓虹光效出现，而是写在具体操作旁边：理解画面、给出候选、保留原图私密。

### 3.2 设计语言

| 项目 | 规范 |
|---|---|
| 背景 | 暖象牙纸 `#F7F1E7`；局部浮层 `#FFFDF8`；暗房区 `#24211D` |
| 文字 | 墨褐 `#211C17`；次级 `#766B5E`；反白 `#FFF9F0` |
| 强调 | 陶土橙 `#BB5834`；只在主操作、序号和当前状态出现 |
| 辅助 | 苔绿 `#667A64`，用于隐私、AI 标识和成功状态 |
| 标题 | 宋体 / Noto Serif SC，字号大、行距紧、允许两行断句 |
| 正文与操作 | PingFang SC / Noto Sans SC，字号克制，避免满屏粗体 |
| 圆角 | 卡片 16 px，按钮 10 px，图片 4–10 px；不做过度胶囊化 |
| 边框 | 1 px 暖灰细线；卡片阴影极浅，以大图和留白建立层次 |
| 图片 | 真实摄影质感，暖高光、青灰阴影、细颗粒；避免塑料皮肤与过度霓虹 |

### 3.3 参考方向

参考来自项目调研文档已经列出的产品形态，并补充照片策展类产品的通用做法：

- **即梦**：作品流中“做同款”的低学习成本，配方继承但可修改。
- **Krea**：左侧工作、右侧画布/结果的结构，参数与结果始终同屏可见。
- **Civitai / OpenArt**：模板题材以封面为主，标签与筛选退居辅助位置。
- **照片策展网站与私人摄影档案**：大尺度图片、少量编辑文字、非均匀网格；资产页应像作品集而不是文件管理器。

这里借鉴的是信息组织和视觉节奏，不复制任何品牌界面、标识或受保护素材。

## 4. 页面方案

### 4.1 首页

1. 顶栏保持极简；左侧印章式“派”字标识，右侧四个主入口与登录。
2. 首屏采用 55/45 不对称双栏：左侧主张与大标题，右侧一张大幅带相纸边框的作品，叠一组小幅修前/修后接触印相。
3. 首屏操作只保留“开始创作”和“一键试玩”，隐私、游客、AI 标识合并成一行微文案。
4. 模板区标题改为“从一张照片开始”，五张封面按杂志书架式排列，首张略大；封面就是页面主角。
5. 页面下方用 01/02/03 解释工作流，不做三张同构功能卡。

### 4.2 创作台

1. 顶部显示步骤轨迹：放入照片 → 理解画面 → 选择方向 → 生成作品；当前步骤有陶土色下划线。
2. 主区左侧是“底图 + 候选”，右侧是固定在视口内的参数与生成按钮。
3. 有底图时直接展示大幅预览和可更换入口；无底图时给出真实示例，而不是空白虚线框。
4. 候选提示词以中文摘要为主，英文块收进高级编辑；模板推荐使用横向电影胶片式卡片。
5. 结果态使用大幅修前/修后对比，右侧“带走这张作品”操作组依次为下载、再生成、存配方、发布社区。

### 4.3 资产库

1. 头部是“我的影像档案”而不是普通列表标题，右侧提供搜索、资产/画册切换和去创作。
2. 顶部给出一组统计：作品数、配方数、画册数；隐私说明保持在近旁。
3. 主体使用瀑布流或不等高六宫格，作品图具有绝对优先级；标签只作为轻量元数据。
4. 第一张卡可以呈“当前精选”，带所用模板、画幅、时间和“再创作”入口。
5. 画册入口以真实翻页书或摊开的相册作为视觉锚点，并明确只使用结果图，不含原图。

### 4.4 社区

1. 顶部用编辑式标题“今天，大家把哪些废片救回来了？”替代后台式“社区”标题。
2. 发现区采用两列/三列不等高作品墙，封面主导；作者、模板、fork 数和标签以极小字号附在下方。
3. 悬停显示“做同款”与“查看配方”；进入详情后显示 fork 谱系，但原图永不出现。
4. 共创任务以“主题刊物”形式出现：标题、策展说明、精选作品三连图和参与按钮。
5. 活动状态要明确：作品公开的是结果与配方，底图仍属于作者。

## 5. 响应式原则

- 桌面：最大内容宽 1280 px，首页双栏，创作台 1fr + 360 px 参数栏，资产/社区三列。
- 平板：首页改为上下结构，模板横向滑动；创作台参数栏折到结果下方。
- 手机：首屏标题不超过三行，主按钮全宽；模板两列；创作台步骤轨迹横向滚动；结果操作固定为底部两组按钮。

## 6. 概念图交付说明

目录 `设计稿/主页面视觉/` 中保存四个主页面的高保真概念图。概念图用于统一视觉方向与汇报表达，不承诺逐像素还原；正式实现时以现有 React 组件和接口为准，中文界面文字由前端排版保证。

对应生图提示词保存在 `设计稿/prompts/`，便于后续重新生成或迭代风格。

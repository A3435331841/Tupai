# 灵感库与社区拆分需求说明（v1 · 可落地）

> 目标：把当前功能混杂的「社区」页拆成两个职责清晰的模块——**灵感库（浏览型）** 与 **社区（社交型）**，并新增**热榜**。
> 本文是需求事实源；现状依据 `代码仓库/web/pages/Community.tsx`、`Library.tsx`、`api/schema-community.sql`、`api/openapi.yaml`。
> 状态：**需求已确认（2026-11-23）**，进入开发；决策见 §8。未提交。

## 0. 为什么要拆（现状问题）

当前 `Community.tsx`（约 972 行）一个页面承载 5 个 tab：

| 现有 tab | 内容 | 性质 |
|---|---|---|
| feed | 用户作品信息流（点赞/评论/搜索/排序） | 社交 |
| showcase | 官方 266 套技能 + 每技能 20 组「原图→作品」示例对、画册 | 浏览/素材 |
| tasks | 共创任务与投稿 | 社交/运营 |
| notify | 通知 | 个人 |
| mine | 我的作品 | 个人 |

问题：① 官方技能/示例这类**静态灵感内容**和用户发帖的**动态社交内容**混在一个 tab 栏，用户找不到；② 用户配方（`SkillRecord`）散在资产库「我的配方」卡里，社区公开的配方无处集中浏览；③ 图片参考没有统一入口；④ 没有热度驱动的内容发现机制。

拆分原则：**灵感库 = 官方 + 公开的可复用素材（只读浏览、可套用/可收藏，无社交互动）**；**社区 = 人 + 动态（发帖、评论、点赞、搜索用户/帖子、热榜）**。

## 1. 模块边界

| 维度 | 灵感库 Inspiration | 社区 Community |
|---|---|---|
| 一句话 | 「找灵感、找配方、找参考」的资料馆 | 「发作品、聊创作、看热门」的广场 |
| 内容来源 | 官方 skills（266）、官方示例对、官方图片参考；社区用户**主动公开**的配方与图片参考 | 用户发布的帖子（作品/图文/文字）、评论、点赞、关注 |
| 内容形态 | 结构化条目（技能卡 / 图片卡 / 配方卡），带分类、标签、封面、示例对 | 信息流卡片（类微博：作者+正文+图组+互动数） |
| 用户动作 | 浏览、筛选、搜索、**套用/收藏/下载参考**（只读，无点赞评论） | 发帖、评论、点赞、转发/做同款、搜索用户与帖子、关注 |
| 是否产生互动数据 | 否（最多记「收藏/使用」计数） | 是（like/comment/repost/follow 全部沉淀） |
| 私密性 | 官方内容全公开；用户内容仅「主动公开」才进入 | 帖子按 `works.status` 与发布可见性控制 |
| 典型入口 | 顶部导航「灵感库」；创作台「找灵感」跳转 | 顶部导航「社区」；作品发布后跳社区 |

**归属裁决（避免扯皮）**：
- 官方 skills / showcase 示例对 / 模板封面 / 授权图片语料 → **灵感库**
- 用户配方（`skills` 表，仅 `visibility=public`）→ **灵感库**（社区发帖可引用它，但不在社区里"管理"）
- 用户作品（`works` 表 published）→ **社区**信息流；其"套用配方/做同款"动作跳转到灵感库或创作台
- 共创任务、通知、我的作品 → **社区**内的次级 tab / 个人中心（保留，不进灵感库）

## 2. 核心功能

### 2.1 灵感库（Inspiration）
- **F1 技能库浏览**：14 类目（创意合成 52 / 人像风格 33 / 趣味玩具化 32 / 插画动漫 28 …）筛选，技能卡显示中文名、描述、封面、标签；点开看 20 组「原图→作品」示例对与画册。
- **F2 图片参考浏览**：官方授权图片参考（1377 张 / 10 类）、模板封面，按分类/标签浏览与大图预览。
- **F3 公开配方浏览**：社区用户标记为公开的配方，展示效果缩略图 + 提示词摘要 + 作者，支持「用这个配方创作」。
- **F4 统一搜索与筛选**：按关键词、类目、标签检索上述三类内容。
- **F5 套用/收藏**：一键把技能或配方带入创作台（`?template=<id>` / `?skill=<id>`）；收藏到个人灵感夹（可选，MVP 可只做本地）。

### 2.2 社区（Community）
- **G1 信息流**：类微博，按时间/热度排序；卡片含作者、正文、图组、作品来源、互动数。
- **G2 发帖**：支持纯文字 / 图文 / 作品带图发布；可带标签、关联作品或配方。
- **G3 评论与点赞**：分页加载评论、发表评论、作者折叠恶意评论、点赞/取消。
- **G4 搜索**：搜帖子（关键词/标签）、搜用户（昵称/ID），结果分栏。
- **G5 热榜**：基于热度算法展示 Top N 帖子/话题，独立入口。
- **G6 次级模块**：共创任务、通知、我的作品（沿用现有，作为社区子 tab 或个人中心）。

## 3. 主要页面与路由

| 页面 | 路由 | 说明 |
|---|---|---|
| 灵感库首页 | `/inspiration` | 三类内容聚合入口 + 类目导航 + 搜索 |
| 技能详情 | `/inspiration/skill/:id` | 技能说明 + 20 组示例对画册 + 套用按钮 |
| 图片参考详情 | `/inspiration/reference/:id` | 大图 + 标签 + 同类推荐（MVP 可合并进列表弹窗） |
| 配方详情 | `/inspiration/recipe/:id` | 配方卡 + 作品示例 + 套用 |
| 社区信息流 | `/community` | 默认首页；时间/热度切换 |
| 帖子详情 | `/community/post/:id` | 正文 + 评论列表 + 互动 |
| 用户主页 | `/community/user/:id` | 该用户帖子、作品、简介 |
| 搜索结果 | `/community/search?q=&type=post\|user` | 帖子/用户分栏 |
| 热榜 | `/community/hot` | Top N 帖子/话题榜 |
| （保留）发布 | `/community` 内弹窗或 `/community/compose` | 发帖入口 |

> 兼容：旧 `/showcase` 301 到 `/inspiration/skill/:id` 或灵感库首页，避免已有画册分享链接失效。

## 4. 关键交互

1. **灵感库 → 创作台**：技能/配方卡点「用这个创作」→ `navigate('/studio?template=<id>')` 或 `?skill=<id>`，创作台自动载入 prompt/模型/画幅。
2. **示例对画册**：技能详情内左右翻阅 20 组原图→作品；点「打开画册」进只读分享页（沿用 `album.share_token`）。
3. **社区 → 灵感**：帖子里的作品卡点「同款配方」→ 跳灵感库配方详情或直接进创作台套用。
4. **发帖**：`+` 发布 → 选文字/图文/作品 → 填正文/标签 → 发布后进信息流顶部；作品类自动带 AI 标识。
5. **互动**：点赞即时乐观更新（本地 +1 / -1），失败回滚；评论分页，作者可折叠恶意评论。
6. **搜索**：顶栏搜索按当前模块上下文分流——在灵感库搜素材，在社区搜帖子/用户；回车触发，不逐字打接口（沿用现有 `applied` 防抖模式）。
7. **热榜**：榜单卡片显示排名、标题、热度值、互动数；点进帖子详情；支持"24h / 7d"时间窗切换（MVP 可固定 7d）。
8. **响应式**：桌面灵感库三栏网格 / 社区两栏（流+侧栏热榜）；移动端单列，互动栏吸底。

## 5. 数据结构

### 5.1 复用现有表（不重复造）
- `app.skills` / `app.showcase_skills`：官方与用户配方/技能（灵感库主数据源）。
- `app.assets`：图片参考与作品资产（`kind=reference|result`）。
- `app.works`：社区帖子主体（已有 `like_count`/`comment_count` 视图字段）。
- `app.likes`、`app.comments`、`app.notifications`、`app.reports`：社区互动（已存在）。
- `app.albums`：画册（技能示例对只读分享）。

### 5.2 需新增/扩展（本次拆分引入）

**帖子表扩展**（若沿用 `works` 作为帖子，加字段；若独立 `posts` 则新建）：
```sql
ALTER TABLE app.works ADD COLUMN IF NOT EXISTS post_type text NOT NULL DEFAULT 'work'; -- work|text|image
ALTER TABLE app.works ADD COLUMN IF NOT EXISTS body text NOT NULL DEFAULT '';          -- 帖正文
ALTER TABLE app.works ADD COLUMN IF NOT EXISTS image_asset_ids jsonb NOT NULL DEFAULT '[]'::jsonb; -- 图组
ALTER TABLE app.works ADD COLUMN IF NOT EXISTS ref_skill_id text;                      -- 关联配方/技能
ALTER TABLE app.works ADD COLUMN IF NOT EXISTS repost_of text;                         -- 转发原帖
ALTER TABLE app.works ADD COLUMN IF NOT EXISTS hot_score real NOT NULL DEFAULT 0;      -- 热度分（见 §5.3）
CREATE INDEX IF NOT EXISTS works_hot_idx ON app.works (hot_score DESC, created_at DESC);
```

**用户资料/关注**（现有 `app.profiles` 仅基础字段，按需扩展）：
```sql
ALTER TABLE app.profiles ADD COLUMN IF NOT EXISTS bio text NOT NULL DEFAULT '';
ALTER TABLE app.profiles ADD COLUMN IF NOT EXISTS avatar_asset_id text;
CREATE TABLE IF NOT EXISTS app.follows (
  follower text NOT NULL, followee text NOT NULL, created_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (follower, followee)
);
```

**收藏/灵感夹**（灵感库 F5，MVP 可延后）：
```sql
CREATE TABLE IF NOT EXISTS app.bookmarks (
  id text PRIMARY KEY, owner_session text NOT NULL,
  target_type text NOT NULL,  -- skill|recipe|reference|work
  target_id text NOT NULL, created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (owner_session, target_type, target_id)
);
```

**热榜快照**（用户确认：定时快照，非实时）：
```sql
CREATE TABLE IF NOT EXISTS app.hot_rank (
  period text NOT NULL, work_id text NOT NULL, rank int NOT NULL, hot_score real NOT NULL,
  computed_at timestamptz NOT NULL DEFAULT now(), PRIMARY KEY (period, work_id)
);
```
定时快照：由维护端点 `POST /api/v1/maintenance/recompute-hot` 触发（可由平台定时任务/手动调用），
计算后一次性写入 `hot_rank`；社区热榜只读快照表，不在用户请求路径上重算。

### 5.3 热度算法（MVP 版）
`hot_score = 3×likes + 2×comments + 1×reposts + 0.5×views − 时间衰减`
时间衰减：`× exp(−age_hours / 72)`（3 天半衰）。定时或按需重算写入 `hot_rank`，社区侧栏与 `/community/hot` 读同一份。

### 5.4 API 端点（新增/调整）
| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/v1/inspiration/skills?category=&tag=&q=` | 灵感库技能列表（复用 showcase_skills） |
| GET | `/api/v1/inspiration/skills/:id` | 技能详情 + 示例对 + 画册 |
| GET | `/api/v1/inspiration/references?category=&q=` | 图片参考列表 |
| GET | `/api/v1/inspiration/recipes?q=` | 公开配方列表 |
| GET | `/api/v1/feed?sort=hot` | 信息流热度排序（现有 sort 扩展 hot） |
| POST | `/api/v1/posts` | 发帖（work/text/image） |
| GET/POST | `/api/v1/posts/:id/comments` | 评论列表/发表 |
| POST | `/api/v1/posts/:id/like` | 点赞切换（现有 works like 复用） |
| GET | `/api/v1/search?q=&type=post\|user` | 统一搜索 |
| GET | `/api/v1/hot?period=7d` | 热榜 |
| POST | `/api/v1/follows/:id` | 关注/取关 |

> 现有 `/api/v1/showcase/skills*` 保留为灵感库数据源兼容层，不必一次性迁移。

## 6. 最小可行版本（MVP）范围

**目标**：验证"浏览与社交分离 + 热榜"这一结构成立，用现有数据和接口最小化改动跑通。

### MVP 必做
1. **导航拆分**：顶部导航由「资产库/社区」调整为「资产库 / 灵感库 / 社区」；`/inspiration` 与 `/community` 独立路由。
2. **灵感库首版**：技能库列表（复用 `GET /showcase/skills`，14 类目筛选 + 搜索）+ 技能详情（现有示例对画册直接搬过来）+ 公开配方列表（复用 `GET /skills` 按 `visibility` 过滤）+ **图片参考独立详情页**（用户确认需要：参考卡 → `/inspiration/reference/:id` 大图 + 标签 + 同类推荐，用授权语料/模板封面）。
3. **社区信息流**：保留现有 feed（作品卡 + 点赞 + 评论 + 搜索 + new/hot 排序），去掉 showcase tab；tasks/notify/mine 暂留为次级 tab。**资产库保持独立**，不并入灵感库。
4. **热榜**：用户确认**定时快照**——新建 `app.hot_rank` 表 + `POST /api/v1/maintenance/recompute-hot` 维护端点算 Top N（含时间衰减），社区右侧栏 + `/community/hot` 只读快照；时间窗固定 7 天。
5. **搜索**：社区搜索先做帖子关键词（现有 `q` 已支持）+ 用户搜索（`profiles` 昵称匹配），结果分栏。
6. **跨模块跳转**：技能/配方「用这个创作」→ 创作台深链；帖子「同款」→ 灵感库配方。

### MVP 明确不做（留后续）
- 发帖的富文本/视频/多图长文（MVP 仅图文 + 作品带图）；
- 关注/粉丝体系、收藏灵感夹（`follows`/`bookmarks` 表先不建）；
- 图片语料全文检索（独立参考详情页本次要做，全文检索留后续）；
- 转发/repost 计数（数据结构预留字段，UI 不露）；
- 旧 `/showcase` 的 301 兼容可后置（先保留原路由）。

### MVP 验收标准
- [ ] 灵感库能按 14 类浏览 266 技能、看示例对画册、套用到创作台；
- [ ] 社区信息流可点赞/评论/搜索、`sort=hot` 生效；
- [ ] 热榜展示 Top 20 且与互动数一致；
- [ ] 两侧内容无交叉混杂，导航与深链可用；
- [ ] `npm run build` 通过、契约测试全绿、repo-scope 门禁 PASS、移动端无溢出。

## 7. 风险与注意

- **数据迁移**：`works` 加字段用 `ADD COLUMN IF NOT EXISTS`，不破坏现有社区数据；`showcase_skills` 保持原样，灵感库只做读取。
- **去重**：官方技能（266）与用户公开配方都叫"配方"，UI 上要区分「官方技能」与「社区配方」，避免用户混淆；`source` 字段是判断依据。
- **AI 标识**：灵感库示例与社区帖子图片沿用既有 `ai_generated` 标识链路，拆页不得绕过。
- **原图私密**：灵感库示例对的"原图"是种子公开语料，与用户私图无关；任何用户私图不得因拆分被曝光。
- **性能**：266 技能 × 20 示例对体积大，灵感库列表必须分页/懒加载，详情按需取，不一次性拉全量。

## 8. 已确认决策（2026-11-23）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 帖子数据表 | **复用 `works` 表**（加 `post_type/body/image_asset_ids/ref_skill_id/hot_score` 字段），不新建 `posts`，改动最小 |
| 2 | 用户配方公开判定 | **用现有 `skills.visibility`** 字段过滤（`public`），不新增标记 |
| 3 | 图片参考详情页 | **需要独立详情页** `/inspiration/reference/:id`，MVP 就做 |
| 4 | 热榜 | **定时快照**：`app.hot_rank` + `POST /maintenance/recompute-hot`，读取不重算 |
| 5 | 资产库 | **保持独立**，不并入灵感库；顶部导航变为 首页/创作台/资产库/灵感库/社区 |

> 以上为最终口径，开发按此执行。

# 图派 · 接口契约 v1

> 版本 v1.0 · 2026-11-17 · 前后端分离的唯一通信约定。
> 机器可读版：`代码仓库/api/openapi.yaml`（✅ 已落盘冻结，12 端点/14 schema，校验通过；mock 见 `代码仓库/api/mock/`。与本摘要不一致时以 yaml 为准并回修本文）。
> **冻结规则：v1 只增不改不删；破坏性变更升 /api/v2。**

## 0. 通用约定

- Base：`/api/v1`；请求/响应均 JSON（上传除外，multipart）。
- **传输前缀（2026-11-17 建点实测）**：Sites 平台保留 `/api` 命名空间，浏览器实际调用同源 `/functions/v1/app/api/v1/*`；云函数剥掉 `/functions/v1/app` 前缀后按本契约 `/api/v1/*` 匹配。逻辑路径与语义不变（openapi.yaml 仅追加 servers 条目，符合只增不改）。
- 游客身份：前端生成 UUID 存 localStorage，每请求带 `X-Session-Id` 头；服务端据此做归属与配额。登录态后期叠加，不改契约结构。
- 错误统一信封：HTTP 4xx/5xx + `{ "error": { "code": "string", "message": "人类可读中文" } }`。
  常用 code：`invalid_input` / `quota_exceeded` / `provider_busy`（限流降级）/ `parse_failed`（链接解析失败）/ `not_found` / `internal`。
- Job 状态枚举：`queued | running | succeeded | failed`。
- 所有结果图 URL 均为本站转存后的 URL（不暴露第三方 COS 直链）。

## 1. 资产

### POST /assets（multipart）
字段：`file`（图片）、`kind` = `original | reference`。
校验：常见图片格式、大小上限（服务端配置）。
```json
→ 201 { "asset_id": "a_xxx", "kind": "original", "width": 3024, "height": 4032,
→        "preview_url": "/api/v1/assets/a_xxx/content" }
```
- `original` 默认私有：content 端点校验会话归属（或签名 URL），不公开可枚举。

### GET /assets/:id/content
返回图片字节（私有校验）；`reference` 的临时公开副本不走此端点（见 §6）。

## 2. 模板与模型

### GET /templates
```json
→ 200 { "templates": [ {
  "id": "night-bright", "title": "夜景提亮", "description": "暗光聚餐照变明亮干净",
  "cover_url": "...", "prompt": "...（图生图）", "negative_prompt": "...",
  "sample_prompt": "...（文生图示意，与封面同源）",
  "variants": [ { "id": "rain-neon", "label": "雨夜霓虹", "prompt": "...", "negative_prompt": "..." } ],
  "default_model": "agnes-image-2.5-flash", "ratio": "3:4", "tags": ["夜景","人像","提亮"] } ] }
```

### GET /models
```json
→ 200 { "models": [ { "id": "agnes-image-2.5-flash", "label": "Agnes Image 2.5", "description": "默认推荐", "default": true },
                     { "id": "agnes-image-2.1-flash", "label": "Agnes Image 2.1", "description": "备选对比" } ] }
```
模型列表服务端白名单控制；前端不硬编码模型 ID。

### GET /quota
```json
→ 200 { "session_used": 2, "session_limit": 20, "global_used": 37,
         "global_limit": 300, "remaining": 18 }
```

## 3. 优化 + 相似推荐（MVP 核心，同步）

### POST /optimize
```json
{ "asset_id": "a_xxx",        // 图片入口（与 text 至少一个）
  "text": "想要胶片感旅行照",  // 文字入口
  "count": 3 }                 // 可选，2–4，默认 3
```
```json
→ 200 {
  "candidates": [ { "summary_zh": "暖调胶片，保留人物与生活场景",
                    "prompt": "...", "negative_prompt": "...", "style_tags": ["胶片","旅行"] } ],
  "recommendations": [ { "type": "template|skill", "id": "night-bright",
                         "title": "...", "description": "...", "cover_url": "...",
                         "cover_private": false, "match_tags": ["夜景","人像"],
                         "score": 0.82, "prompt": "...",
                         "negative_prompt": "...", "model": "...", "ratio": "3:4" } ],
  "recommendations_fallback": false,
  "mode": "img2img|txt2img"    // 有底图=img2img，纯文字=txt2img
}
```
- 无相似匹配时返回 5 个模板兜底并置 `recommendations_fallback: true`；创作台用「没有完全匹配的，试试这些模板」展示，不挡主路径。
- 模板推荐携带 `sample_prompt/variants`；Skills 推荐携带完整配方字段与私有封面标记。
- 耗时预期 3–10s；前端 loading；超时/`provider_busy` → 前端展示降级候选（契约附 mock 样例）。

## 4. 生成（异步 Job）

### POST /jobs/generate
```json
{ "asset_id": "a_xxx",          // 可选；缺省=文生图
  "prompt": "...", "negative_prompt": "...",
  "model": "agnes-image-2.5-flash", "ratio": "3:4" }
→ 202 { "job_id": "j_xxx", "status": "queued" }
```

### GET /jobs/:id
```json
→ 200 { "job_id": "j_xxx", "status": "succeeded",
         "result": { "asset_id": "a_yyy", "url": "...", "width": 864, "height": 1152 },
         "error": null }
```
- `failed` 时 `error` 为错误信封结构；前端提供重试（重新 POST generate）。
- 轮询间隔建议 2s；前端 120s 未终态提示超时文案，并把 job 存入「上次生成」供继续。
- 前端 localStorage 保存最近一次 job 元数据；刷新可恢复结果或继续轮询，避免配额白扣。

## 5. Skills

### GET /skills（我的配方）
```json
→ 200 { "skills": [ { ...tupai-skill-v1, "skill_id": "s_xxx", "style_tags": ["夜景","人像"],
                       "cover_url": "/api/v1/assets/a_xxx/content", "created_at": "..." } ] }
```
仅返回当前游客会话的配方（最新 50 条）。

### POST /skills（保存）
body = tupai-skill-v1 JSON（见需求文档 §5.1，format/version 必填）。
```json
→ 201 { "skill_id": "s_xxx" }
```

### POST /skills/import（校验导入）
body = 用户上传的 tupai-skill JSON。
```json
→ 200 { ...原字段, "skill_id": "s_xxx" }   // 直接回填创作台
→ 422 { "error": { "code": "invalid_input", "message": "缺少 prompt 字段" } }
```
前端会把无法识别的模型自动落到默认模型并提示。

### GET /skills/:id
```json
→ 200 { ...tupai-skill-v1 字段, "skill_id": "s_xxx" }
```

### GET /skills/:id/skill.md
`Content-Type: text/markdown` → Agent Skills 格式 SKILL.md 文本（前端触发下载）。

## 6. 链接解析（扩展，尽力而为）

### POST /links/parse
```json
{ "url": "https://v.douyin.com/xxxx/" }
→ 200 { "source_url": "...", "text": "文案（可能为空）",
         "images": [ { "temp_url": "...", "expires_at": "2026-11-17T12:00:00+08:00" } ] }
→ 422 { "error": { "code": "parse_failed", "message": "解析失败，请直接上传图片或文字；视频请截帧上传" } }
```
- 仅抖音单条图文帖；`temp_url` 为临时对象，生命周期 ≤ 单个 Job，过期/用后即删。
- 前端拿 images 走正常上传/optimize 流程；**解析内容不落 Asset 库**。
- 此端点失败不影响任何 MVP 路径。

## 7. 契约治理

1. 变更流程：改 `openapi.yaml` → 前后端双方确认 → 各自实现 → 契约测试通过 → 合并。
2. 前端 mock：`api/mock/` 按本契约提供全端点样例响应（含失败/限流分支），前端开发期默认走 mock，一键切真实后端。
3. 后端契约测试：对每个端点断言响应结构与枚举值；CI/发布前必跑。
4. 新增端点/可选字段：小版本递增（v1.1…）；改语义/删字段：禁止，升 v2。

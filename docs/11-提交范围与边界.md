# 图派 · GitHub 提交范围与边界

> 版本 v2.1 · 2026-11-18。目标是让公开仓库可以构建、验证并追溯必需资产，同时减少重复副本和过程材料。
> 资产库已按 [`docs/13-创意资产库结构与命名规范.md`](13-创意资产库结构与命名规范.md) 全面中文化重组；命名与状态规则以 docs/13 和本地 `AGENTS.md §6` 为准。

## 1. 应公开的内容

- `README.md`、`LICENSE`、`.gitignore.example`，以及维护、使用、验收所需的项目文档。
- `代码仓库/web/` 的源码、锁文件和 `public/` 运行时资源，`server/`、`api/` 和必要的开发、验证脚本及发布元数据。
- `资产仓库/` 中运行时资源对应的源文件、来源和许可记录、资产与运行时映射清单；当前设计索引和维护原型所必需的文件。
- README 已引用的代表性截图及确有维护价值的既有资料。是否保留以实际引用、独有源文件和复现需要为准，不按目录整批提交。

`web/public/` 是运行时副本，源文件仍在 `资产仓库/`；源文件与运行时文件都要纳入，以便公开克隆能够构建并追溯。第三方资料应保留适用的来源与许可说明。

## 2. 默认仅留本地

- Key、Secret、`.env*`、私钥、`docs/references/agnes-api.md`、用户私图、`资产仓库/95-私有资产/`（本地测试底图与私图）。
- 本地 `AGENTS.md`、`.gitignore`、`.workbuddy/`、`.workbuddy-ai/`、早期规划、浏览器缓存、日志、依赖和构建产物。
- 新增的原型素材重复副本、设计/品牌探索、历史归档、批量预览、模板回归样片，以及 PSD、AI、ZIP、MP4 等大型过程文件。确需公开时先确认来源、用途及依赖，并有意识地调整边界与清单。

公开仓库提供的 `.gitignore.example` 是通用样例，不包含用户的本地私有配置。新克隆应先检查并复制或合并为本地 `.gitignore`；已有 `.gitignore` 不要覆盖。范围脚本只检查已暂存/已跟踪的内容，不会保护尚未暂存的文件，也不能替代敏感值审查。

## 3. 本次缩减与历史

首页原型 `assets/` 中 24 个文件与现有 Logo、模板源图或画廊源图的 SHA-256 一致，合计 14.65 MiB；这些副本从当前提交树移出，原型引用改指已跟踪源文件。素材清单仍保留它们的记录并标注 `repository_scope: local-only`。本地原文件保留；其他独有或用于追溯的原图继续跟踪。

本地使用 `git rm --cached` 可保留工作区文件。其他已有克隆从旧版本切换或拉取包含删除的提交时，Git 可能移除对应工作区路径；需要本地副本的使用者应在切换前自行保存。新克隆不会得到标为仅本地的副本，但当前原型和运行时引用的源文件都在仓库中。

此操作只缩减当前文件树，不会从既有 Git 历史中删除这些对象，也不保证降低普通完整克隆的历史下载量；不重写或强推已有历史。其余已跟踪的历史过程文件暂留；新增同类文件默认受检查脚本阻断。

## 4. 新素材与清单

1. 先检查 `资产仓库/90-元数据/资产总清单.json` 的 sha256 与六维标签，已有内容优先复用；需要派生时记录 `派生自`。
2. 需要运行的素材先落唯一源，再同步 `web/public/`，维护 `90-元数据/运行时映射.json` 的 `runtime_path`、`source_path` 和 sha256（public 路径保持英文不变）。
3. 新资产按 docs/13 落入中文目录与六态分区，状态在目录、清单字段、版本说明三处同步；清单条目标 `可见性=private` 的为本地保留，公开克隆可缺少；其他清单路径和所有运行时映射源必须在 Git 暂存树中存在。
4. sha256 对照 Git 对象的字节。Windows 自动换行转换可能使工作区 SVG 的文件哈希不同，不应直接把这种差异当成资产损坏。
5. 新增单文件超过 5 MiB 告警，超过 50 MiB 阻断。已有的重复图片仅告警；新增重复源图片阻断。运行时副本不计入资产源重复判定。

## 5. 提交前检查

```bash
# 明确选择文件后，检查实际暂存内容
git add -- <明确路径>
node 代码仓库/dev/repo-scope-check.mjs
node 代码仓库/dev/repo-scope-check-test.mjs
git diff --cached --check
git diff --cached --stat
git status --short
```

脚本检查禁止路径、新增过程材料、文件大小、新增重复图片、资产清单及运行时映射；读取 Git 暂存对象而非工作区同名文件。`--strict` 将大文件告警视为失败，既有重复组仍只告警。脚本并不扫描全部敏感值、判断授权或检测历史提交中的泄露，提交前仍需人工检查内容和来源。

产品代码变动还需构建并执行相应契约及回归验证；上传或发布前核对实际结果。已发布历史不重写、不强推；新增提交使用项目约定的中文标题。

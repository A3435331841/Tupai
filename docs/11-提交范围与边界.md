# 图派 · GitHub 提交范围与边界

> 版本 v1.0 · 2026-11-18 · 状态：**定稿**
> 本文接替同路径的《提交范围与文档同步方案（待确认）》，与 [docs/04-资产与数据](04-资产与数据.md) 配套；本地 `AGENTS.md` / `.gitignore` 为私有文件，不随 GitHub 发布。
> 目标：GitHub 只承载**可运行产品、唯一资产源、必要文档与可复现验证**；过程产物、私密素材与本地状态留在本地。

---

## 1. 总原则

1. **可复现**：克隆仓库后能构建、能跑本地 fake、能跑契约与回归测试。
2. **唯一源**：`资产仓库/` 是资产唯一源；`代码仓库/web/public/` 只是运行时副本，不能作为第二份源。
3. **隐私与协议**：Key、私图、用户废片、未授权素材永不入库；第三方素材必须有来源与协议记录。
4. **历史不重写**：已推送的 Git 历史不覆盖、不强推、不 `filter-branch`。边界规则约束**后续提交**，不通过重写历史来“瘦身”。
5. **批次可审查**：用 `git add -- <明确路径>`，每批只做一类改动；禁止 `git add -A`。

## 4. 大文件与格式规则

| 规则 | 阈值/要求 |
|---|---|
| 单文件告警 | > 5 MB |
| 单文件阻断 | > 50 MB（GitHub 另对 >100MB 硬拒绝） |
| 图片格式 | 运行时优先 `.webp`；源图可用 `.jpg/.png`；新增不提交 `.psd/.ai/.zip/.mp4` |
| 目录体积 | 新增批次建议 ≤20 MB；超过时拆分或改为本地保留 |
| 重复检测 | 新图片先查 `资产清单.json` 的 sha256；命中即复用 |
| 运行时副本 | 每个 `web/public/` 文件必须在 `运行时映射.json` 有 `runtime_path → source_path` |

## 5. 新资产/新文件判定流程

```text
新素材
 → 查资产清单 sha256
   → 命中：复用，不复制
   → 未命中：判断复用 / 派生 / 新生成
      → 派生：media/derived/ + derivative_of
      → 新生成：落 资产仓库/，写 manifest（含 sha256）
 → 同步 代码仓库/web/public/（路径保持英文）
 → 更新 manifests/运行时映射.json（runtime_path/source_path/sha256）
 → 更新页面 索引.md / 版本说明.md（如涉及设计版本）
 → 跑 build + 资源 404 + repo-scope-check
```

命名遵循 AGENTS §6：**资产文件中文、技术标识英文**；`templates/<id>/` 目录名必须是 API id。

## 6. 提交前检查

```bash
# 1. 范围与边界（禁止路径、未知顶层、超大文件、重复图片）
node 代码仓库/dev/repo-scope-check.mjs

# 2. 工作区与暂存区
git status --short
git diff --cached --stat

# 3. 空白错误
git diff --check

# 4. 敏感值扫描（应为空）
git grep -Il "sk-[A-Za-z0-9]\{20,\}" -- .
```

**提交纪律**：

- 只用 `git add -- <明确路径>`；禁止 `git add -A` / `git add .`。
- 资产移动、文档、代码、发布记录分开提交。
- **提交标题使用中文**：`中文类型(范围): 中文摘要`，如 `修复(资产): 修正清单引用`；禁止 `fix/docs/feat` 等英文类型前缀（历史提交不追溯改写）。
- 不覆盖、不强推、不重写已推送历史。
- 提交完成后 `git status --short` 必须干净（仅允许用户明确保留的未跟踪文件）。

## 7. 例外与审批

以下操作必须得到用户明确确认，并在提交说明/文档中记录：

1. 新增超 20MB 的资产批次；
2. 将过程产物（原型副本、探索图、归档）重新纳入版本控制；
3. 清理已跟踪的大体积历史文件（只做 `git rm --cached` 不足以瘦身，需说明历史策略）；
4. 公开任何含真人肖像、第三方素材或本地测试集的资产。

**永不例外**：Key、`.env`、私图、未授权素材、`docs/references/agnes-api.md`。

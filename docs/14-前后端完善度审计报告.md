## 0. 结论摘要

- 主链路（上传 → 优化 → 生成 → 下载 → 配方 → 发布 → 社区 → 画册分享）是真实可用的，前端构建与既有契约测试曾全绿。
- 最大的问题不是「缺页面」，而是**入口与结果不对齐**：点赞态、评论作者、通知跳转、单作品分享、配方/作品编辑、画册编辑等只有半边；顶栏与创作台存在多个静态按钮冒充功能。
- 存在一个会直接影响演示的功能阻断：**画册分享页图片使用了根路径 `/api/v1/...`**，而站点 API 实际挂在 `/functions/v1/app` 下，生产环境分享页图片会 404。
- 正确性风险集中在：软删资产仍可读取/发布/入册、上传不校验真实文件类型、链接解析缺少限流与重定向复检、任意上游异常被降级为「演示占位图」并计配额、AI 标识只在创作台下载时合成。
- 建议按「闭环基础 → 管理能力 → 体验清理 → 安全一致性 → 可选增强」五批推进，批次内接口只增不改。

## 3. 功能闭环问题（第一优先级）

### F-01 社区点赞状态不闭环

- **现象**：点赞按钮永远是「♥ 点赞」，弹窗内不显示当前状态与计数；点赞后只刷新列表，已打开的作品对象不更新。
- **证据**：[`Community.tsx`](../代码仓库/web/pages/Community.tsx) 第 72-75、291 行；[`routes.mjs`](../代码仓库/server/routes.mjs) 第 82-90 行的 `workMeta` 没有 `liked`，第 1004-1014 行只返回本次操作结果。
- **影响**：用户无法判断自己是否点过赞，容易重复点击；详情与列表数据不一致。
- **方案**：`workMeta` 增加只读 `liked`（按 `viewerKey` 查询当前会话/用户，列表用一次批量查询）；前端切换按钮文案与计数，并同步 `active`；OpenAPI 与 `types.ts` 只增字段。
- **验证**：点赞 → 关闭 → 重开仍显示已赞；列表与详情计数一致。

### F-02 评论缺少作者与时间，且无分页

- **现象**：评论区只渲染正文，无法判断谁在评论；超过 100 条被截断且无法加载更多；删除/隐藏后计数不刷新。
- **证据**：[`routes.mjs`](../代码仓库/server/routes.mjs) 第 970-989 行只返回 `author_id`；[`Community.tsx`](../代码仓库/web/pages/Community.tsx) 第 311-317 行只渲染 `c.body`。
- **影响**：评论缺乏上下文，社区感弱；长评论串直接消失。
- **方案**：评论查询返回 `author_name`（显示名/`author_credit`）与 `created_at`，增加 `limit/offset`；前端显示作者、时间与「加载更多」，操作后刷新计数。
- **验证**：两个账号互评能看到对方名称；刷新后顺序与时间正确。

### F-03 通知没有未读数、不能跳转、不能全部已读

- **现象**：顶栏铃铛红点常亮，但与真实未读无关；通知卡片没有点击行为；只能逐条「标为已读」。
- **证据**：[`SiteHeader.tsx`](../代码仓库/web/components/SiteHeader.tsx) 第 186-193 行；[`Community.tsx`](../代码仓库/web/pages/Community.tsx) 第 245-255 行；[`routes.mjs`](../代码仓库/server/routes.mjs) 第 1060-1071 行。
- **影响**：点赞/评论/fork 通知实际不可消费，社交回路断裂。
- **方案**：`GET /notifications` 增加 `unread` 计数，新增 `POST /notifications/read-all`；顶栏拉取未读数并跳 `/community?tab=notify`；卡片点击按 `work_id` 打开作品；补「全部已读」。
- **验证**：他人点赞/评论后顶栏数字变化；点击通知打开对应作品；全部已读后红点消失。

### F-04 资产库仍是 `confirm/prompt`，统计口径错误

- **现象**：删除资产用 `window.confirm`，打标用 `window.prompt`；「件作品」实际统计全部资产（含原图/参考图）；回收站无彻底删除/清空。
- **证据**：[`Library.tsx`](../代码仓库/web/pages/Library.tsx) 第 54、63、85、100 行。
- **影响**：交互风格与全站设计稿不一致；移动端原生弹窗体验差；删除语义只有「软删」。
- **方案**：用现有 `Dialog + Input` 替换；统计文案改「资产」并区分原图/作品；新增彻底删除接口或在回收站逐条 purge；空态与错误态分离。
- **验证**：删除/打标弹层可键盘操作；统计数与筛选结果一致；彻底删除后存储与记录均消失。

### F-05 画册不可编辑、分享能力不完整

- **现象**：画册只能建/删/分享/撤回，不能改名、增减作品；分享有效期固定 7 天不可选；已有 token 不能重新复制链接；剪贴板失败仍提示成功。
- **证据**：[`AlbumsPanel.tsx`](../代码仓库/web/components/AlbumsPanel.tsx) 第 46-67、122-128 行；后端已支持 `PATCH /albums/{id}`（[`routes.mjs`](../代码仓库/server/routes.mjs) 第 747-762 行）和 `expires_hours`（[`api.ts`](../代码仓库/web/lib/api.ts) 第 90 行），前端未使用。
- **影响**：画册做出来后无法维护，只能删了重建；分享链接丢失只能撤回重发。
- **方案**：画册卡增加「编辑」（标题 + 条目复选）与「复制链接」；分享弹层提供 1 天/7 天/30 天；`navigator.clipboard` 失败回退手动复制提示；单张下载与 zip 导出列为后续。
- **验证**：改名与增减作品后刷新保持；不同有效期分享按预期过期。

### F-06 作品没有独立路由与单作品分享

- **现象**：作品只能在社区弹窗查看，刷新即丢失，无法把单个作品链接发给别人；`/works/{id}` 仅是 API。
- **证据**：[`Community.tsx`](../代码仓库/web/pages/Community.tsx) 第 280-329 行；[`App.tsx`](../代码仓库/web/src/App.tsx) 第 21 行没有作品路由。
- **影响**：作品无法在站外传播；社区内容不可被搜索引擎或收藏夹定位。
- **方案**：新增 `/work/{id}` 页面（复用现有详情内容），作品卡与详情提供「复制链接」；非公开作品按当前登录态返回 404/提示。
- **验证**：直接访问 `/work/wk_...` 可打开；刷新与分享链接一致。

### F-07 配方与已发布作品不可管理

- **现象**：配方只能新增/套用/导出，无法改名或删除；作品发布后标题、标签、allow_fork 均不可改，只能删除重发。
- **证据**：[`routes.mjs`](../代码仓库/server/routes.mjs) 第 675-687 行仅 GET；[`api.ts`](../代码仓库/web/lib/api.ts) 无对应方法；[`Community.tsx`](../代码仓库/web/pages/Community.tsx) 第 266-272 行只有撤回/重发/删除。
- **影响**：配方库越积越乱；发布后发现标点/标签问题只能重建作品，丢失点赞与评论。
- **方案**：新增 `PATCH/DELETE /skills/{id}`、`PATCH /works/{id}`（只允许 title/tags/allow_fork，不改 status）；前端「我的配方」「我的作品」增加编辑入口。
- **验证**：非 owner 返回 404；修改后列表与详情同步。

### F-08 共创任务没有生命周期

- **现象**：任务只能创建和投稿，不能关闭/重开，不能撤销投稿，没有截止时间与投稿数；前端创建时不能填约束。
- **证据**：[`routes.mjs`](../代码仓库/server/routes.mjs) 第 1016-1058 行；[`Community.tsx`](../代码仓库/web/pages/Community.tsx) 第 100-113、222-240 行。
- **影响**：共创活动无法收尾；误投无法撤回；用户看不到参与规模。
- **方案**：新增 `PATCH /tasks/{id}`（owner 关闭/重开）、`DELETE /tasks/{id}/submissions/{workId}`；列表显示投稿数；创建弹层增加约束输入。
- **验证**：关闭后不能再投稿；撤销后详情列表减少。

### F-09 账号资料与身份展示缺失

- **现象**：`profiles` 表建了但无接口；顶栏登录态只显示一行文字，无头像/退出；创作台左下角硬编码「jia xin xiao」与字母头像。
- **证据**：[`schema-community.sql`](../代码仓库/api/schema-community.sql) 第 111-117 行；[`routes.mjs`](../代码仓库/server/routes.mjs) 第 1138 行仅删除；[`SiteHeader.tsx`](../代码仓库/web/components/SiteHeader.tsx) 第 109-119 行；[`BotStudio.tsx`](../代码仓库/web/pages/BotStudio.tsx) 第 1063-1065 行。
- **影响**：登录与未登录体验割裂；用户无法修改昵称/头像；演示时可能误展示他人姓名。
- **方案**：新增 `GET/PATCH /me/profile`；顶栏与创作台使用 `api.me()` 渲染昵称/头像，未登录显示「游客」；补退出入口。
- **验证**：登录后昵称/头像一致；未登录不显示他人信息；退出后回到游客态。

### F-10 画册分享页核心资源路径错误（功能性阻断）

- **现象**：分享页 HTML 中图片写死 `/api/v1/share/{token}/img/{id}`；但站点 API 实际挂在 `/functions/v1/app`，根 `/api` 被平台保留，生产打开分享页图片会 404。
- **证据**：[`routes.mjs`](../代码仓库/server/routes.mjs) 第 98、810-813 行；[`api.ts`](../代码仓库/web/lib/api.ts) 第 4-6 行明确注释 `BASE = '/functions/v1/app'` 且 `/api` 由平台保留。
- **影响**：画册「只读分享」是参赛演示链路之一，当前在生产可能只有文字没有图。
- **方案**：分享页图片改用相对当前页面的 `img/{assetId}`（或由服务端注入正确前缀）；同时给每图与页脚加 AI 标识。
- **验证**：通过 `apiUrl(share_page)` 打开页面，浏览器 Network 中图片全部 200。

### F-11 创作台会话与状态不持久

- **现象**：对话、Bot 状态、已选模板、暂停开关、头像、记忆全部是内存态，刷新即回到脚本化初始对话；「上次任务」只恢复生成参数/结果，不恢复对话。
- **证据**：[`BotStudio.tsx`](../代码仓库/web/pages/BotStudio.tsx) 第 764-771、803-822、1359-1373 行；[`AvatarEditorDialog.tsx`](../代码仓库/web/components/AvatarEditorDialog.tsx) 第 81-90 行。
- **影响**：刷新/误关页面后上下文全丢；用户需要重新描述诉求；演示时看起来像「预设假对话」。
- **方案**：短期把 `turns/avatars/memory/paused` 写入 `localStorage`（按任务 ID）；中期再考虑服务端会话。刷新后恢复最后任务对话与产物。
- **验证**：发消息 → 刷新，对话与状态保留；头像与记忆保留。

## 4. 体验与清理问题（第一优先级）

### E-01 顶栏假入口

- **现象**：搜索框可输入但无提交行为；铃铛无点击；帮助按钮无点击；登录后无头像/菜单/退出。
- **证据**：[`SiteHeader.tsx`](../代码仓库/web/components/SiteHeader.tsx) 第 177-201、109-119 行。
- **影响**：用户会反复尝试搜索与通知，形成「功能坏了」的印象。
- **方案**：搜索接 `/community?q=`；铃铛接通知页并显示真实未读；帮助跳 `/legal`；登录态改为头像菜单（资料/退出）。未实现前至少 `disabled` 并给出说明。
- **验证**：每个控件点击都有可见结果或明确禁用态。

### E-02 创作台假功能与误导态

- **现象**：分享按钮无 `onClick`；语音按钮无禁用且提示「即将上线」；「暂停」开关不阻止派单/轮询；应用矩阵中「创作台/模板/设置」无行为；首次进入自动塞入示例图并进入 ready；Bot 回复为固定脚本。
- **证据**：[`BotStudio.tsx`](../代码仓库/web/pages/BotStudio.tsx) 第 1087-1089、1257-1259、1306-1309、1036-1041、803-822、856-875 行。
- **影响**：最核心页面出现「点了没反应」，且自动示例态可能让用户误以为已上传自己的照片。
- **方案**：分享接「发布社区」或复制成品链接；语音禁用并加 `title`；暂停真正阻断 `dispatchToArtist/pollJob`；应用矩阵只保留已实现项；示例态改为可关闭引导条且不写入真实 `file/prompt`；脚本回复加「演示编排」标识。
- **验证**：暂停时不会新增 job；关闭引导后不出现示例图；点击每个矩阵项都有结果。

### E-03 错误态被示例内容掩盖

- **现象**：社区 feed 请求失败时 `setWorks([])`，直接展示示例作品墙；用户无法区分「没有内容」与「接口故障」；首张示例大图未标「示例」。
- **证据**：[`Community.tsx`](../代码仓库/web/pages/Community.tsx) 第 56-59、150-186 行；[`Library.tsx`](../代码仓库/web/pages/Library.tsx) 第 37-40、111-148 行。
- **影响**：线上故障会被误判为「社区没人」，也掩盖了接口错误。
- **方案**：增加 `error` 状态与重试按钮；示例墙只在成功且为空时展示，并统一标注「示例」；错误文案区分网络/登录/服务。
- **验证**：断网刷新社区显示错误与重试，而不是示例墙。

### E-04 资产库空/错态与操作反馈

- **现象**：加载失败只 toast，列表空态与真正的「无资产」不可区分；删除/恢复后滚动位置与总数跳变；没有单资产预览/下载。
- **证据**：[`Library.tsx`](../代码仓库/web/pages/Library.tsx) 第 30-41、107-182 行。
- **影响**：资产管理效率低；用户无法确认某张图是哪次生成的。
- **方案**：区分 loading/error/empty；增加资产预览 Dialog 与下载（走 blob）；操作后保留滚动位置。
- **验证**：失败态可重试；预览可下载且文件名合理。

### E-05 未知路由静默回首页

- **现象**：`/foo`、`/studioo` 均渲染首页且 HTTP 200，用户与搜索引擎无法识别错误。
- **证据**：[`App.tsx`](../代码仓库/web/src/App.tsx) 第 21 行三元回退 `<Home/>`。
- **影响**：输错地址或旧链接不会提示；埋点与 SEO 失真。
- **方案**：增加 `NotFound` 页面与路径白名单；未命中显示 404 与返回入口。
- **验证**：访问 `/unknown` 显示 404。

### E-10 分享与下载的合规标识不完整

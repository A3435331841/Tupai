## 1. 豆包P图爆款玩法调研（模板与验收参考）

### 1.1 热度与代表玩法

「把图片交给豆包」类指令帖在小红书/微博/抖音持续爆火（单帖数万赞、数万收藏）。已核实的热门玩法：

| 玩法 | 说明 | 对图派的意义 |
|---|---|---|
| 换背景/换天空/改光线 | 「玻璃海」「蓝天白云晚霞」「室内暗照补逆光」，爆款指令公式：换天+换水+「消除路人和杂物」 | **主场需求**，废片改造第一场景 |
| 去路人/去杂物 | 旅游照一句话清场 | 高频、低风险（不改主体） |
| 风格化氛围 | 复古 CCD、动漫风、海报感、「朋友都以为我拍了写真」 | 与图派模板库直接对应 |
| 日常快照写真 | 「以上传的照片人物为原型…日常快照风格…运动模糊轻微过曝，似 iPhone 随意抓拍」 | 与 Portra 胶片风格卡同构，验证了「胶片日常」模板方向 |
| 蜡笔涂鸦丑萌风 / AI合照二次元 | 抖音传播度最高的娱乐向玩法 | 二期娱乐模板候选（一期先做质感向） |

### 1.2 关键方法论（直接采纳进 optimize 设计）

社区高赞共识 + 翻车分析（smzdm 2026-08-29 汇总 16 位作者）：

1. **AI 擅长改「环境」（背景/光线/风格），不擅长改「主体」（脸/身材/手指/细节）。**
   → 图派一期模板全部走「改环境不改主体」路线；证件照、瘦脸瘦身、商业产品图明确不做（写入模板「不适用」说明）。
2. **指令三步法**：①一次只派一个任务；②明确说「不改什么」（如「保留人物的脸部、表情、服装不变」「以上传的照片人物为原型」）；③重生成 3–5 次不行就换思路。
   → 落到开发文档 §4.6 optimize：每个候选 prompt 必须带**保留约束句**（负面词/不变项），候选之间是「单任务变体」而不是「多任务叠加」；UI 提供「再来一次」低成本重试。
3. 行业趋势是卷「保真」（修完还是你），「五官不变」是公认短板。
   → M3 回归验收加一条：**人脸相似度主观检查**（用户验收 U，M3-6），翻车样片不入模板库。

### 1.3 验收基准

模板样片的验收对标爆款帖效果：「朋友以为我拍了写真」级别的氛围感，同时通过 1.2-3 的保真检查。爆款提示词原文属第三方作者，**不复制入库**，只作为风格基准参考（出处记录见 `资产仓库/skills/third-party/来源说明.md` §3）。

## 4. 前端设计参考

### 4.1 核心借鉴：即梦「做同款」交互（与图派 MVP 流程同构）

即梦（jimeng.jianying.com，抖音旗下）的已验证交互路径：

1. **发现页瀑布流**展示社区作品/模板，hover 出「做同款」按钮；
2. 点击后**自动继承提示词+模型+比例+风格参数**进入生成预备窗；
3. 用户只改可变部分（换主体/换场景），或「使用提示词」只带词不带参考图；
4. 生成约 10 秒出 **4 张候选**，长按可看所用参数；
5. 参考强度滑杆：70–90% 更像原版，30–50% 更有创意。

→ **图派直接映射**：模板推荐卡 = 瀑布流里的「作品」；「一键同款」= 我们的推荐预览→微调→生成；候选 2–4 张 = optimize count 参数；「继承参数但可改」= 契约里 recommendations 携带默认 prompt/ratio/model。这套交互已被市场验证，评委/用户零学习成本。

### 4.3 落到图派 SPA 的具体设计决策（供 M1 前端执行）

1. **创作区三入口**：上传图 / 输文字 /（扩展）贴链接——大按钮+拖拽区，首屏即达。
2. **optimize 结果页**：2–4 个候选 prompt 卡片（可编辑文本域）+ 相似模板推荐横排（封面+名称+tags+「一键同款」）。
3. **生成页**：左参数（候选词/比例/模型只读白名单）右预览；8–20s 进度态用骨架屏+阶段文案（「分析画面→优化提示词→生成中」），失败给明确错误码文案（契约 §error）。
4. **结果页**：修前修后对比滑杆（醒图式）+ 下载 + 「存为 Skill」。
5. 视觉基调：浅色暖灰底+一个强调色（胶片/氛围感产品调性），模板封面网格是首页主角；深色创作台为可选主题，一期不做。
6. 移动端优先适配（参赛演示大概率手机打开）：瀑布流单列、参数面板折叠为底部抽屉。

## 5. DeepSeek 搜索服务调研结论

调研对象：https://api-docs.deepseek.com/zh-cn/guides/search （已完整读取官方文档）。

### 5.1 事实

- 两个独立工具端点：`POST https://api.deepseek.com/v1/tools/search`（网页搜索）与 `/v1/tools/fetch`（抓网页转 Markdown），Bearer 认证，与 chat 模型分开计费。
- **价格：¥5 / 1000 次成功请求**（仅 HTTP 200 且有结果才计费），需账户充值余额；QPS 上限 search 100 / fetch 25。
- 支持查询语法（`site:`、`lang:`、`after:` 等），结果带 rerank_score/summary/content/authority。
- **Search API 不含图片搜索**（图片搜索只存在于 chat 的 web_tools 内，且同样计费）。
- 另有 DeepSeek chat 模型本身（V3/R1 系列）按 token 计费，非免费。

### 5.2 结论：**MVP 不内置**（建议采纳）

| 理由 | 说明 |
|---|---|
| 要花钱 | ¥5/1000 次 + 需维护充值余额，违背「一期只用 Agnes 免费服务」的已拍板约束 |
| 无图片搜索 | 图派最需要的是「找相似视觉参考」，Search API 给不了 |
| 能力重叠 | 文本理解/prompt 优化 Agnes `agnes-3.0-flash` 已免费覆盖 |
| 多一套 key 管理 | 新增 Secret、限流、错误处理面，M0–M3 工期不值 |

### 5.3 后续可选（不承诺）

- **二期「灵感搜索」**：用户输入「最近流行什么风格」→ search 拉趋势文章 → Agnes 总结成模板候选。届时按量付费可控（每次创作 1–2 次请求）。
- **链接解析辅助**：fetch 理论上可抓图文页，但抖音反爬对数据中心 IP 同样生效，且 GPL/合规边界不变——**不改变 M0-9 spike 的自建轻量解析方案**。
- 若未来开放 BYO 模型（三期），DeepSeek 可作为用户自带 key 的文本供应商之一，与搜索服务无关。

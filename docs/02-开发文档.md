## 1. 总体架构（单轨 Sites + 前后端分离，已拍板）

- **全链路用 Qoder 开发**，代码在本目录 `代码仓库/`，资产在 `资产仓库/`。
- **前后端分离**：前端是纯静态 SPA，后端是独立 API 服务，两者只通过冻结的 API 契约（[07-接口契约](07-接口契约.md)）通信。**接口不变的前提下，前后端可各自独立修改、独立部署、独立回滚。**
- **部署 Qoder Sites**：前端静态产物 + 后端云函数 + 数据库 + 对象存储 + Secret，访问策略 public。不做第二个仓库、不做演示壳。
- 后端内部保留两处抽象以便日后迁出/换模型：**ImageProvider**（出图/优化）与 **AssetStore**（资产读写）。业务代码禁止直调 Agnes SDK。

```
┌─ 前端 web/（纯静态 SPA，可独立换框架）────────────┐
│  Vite + React + TS + Tailwind + shadcn/ui        │
│  只依赖 /api/v1 契约；开发期用契约 mock           │
└──────────────┬─────────────────────────────────┘
               │ HTTPS · /api/v1（OpenAPI 契约冻结）
┌─ 后端 server/（Sites 云函数，可独立重写）─────────┐
│  路由层（契约实现，薄）                           │
│   ├─ Job 服务（DB 记任务 → 执行 → 轮询）          │
│   ├─ Prompt 优化器 + 相似检索（打标/匹配）        │
│   ├─ 链接解析器（扩展：抖音图文，用后即焚）       │
│   ├─ ImageProvider ──► Agnes API（Key 池）       │
│   │      └─ MockProvider（兜底）                 │
│   └─ AssetStore ──► Sites 对象存储               │
│  Sites 数据库 / Secret                           │
└─────────────────────────────────────────────────┘
```

### 代码目录

```
代码仓库/
```

### 契约治理规则

1. `api/openapi.yaml` 是唯一事实源，文档版摘要见 [07-接口契约](07-接口契约.md)；两者不一致时以 yaml 为准并修文档。
2. 路径统一 `/api/v1` 前缀；v1 冻结后**只增不改不删**（新增可选字段/新端点允许）。
3. 破坏性变更必须升 `/api/v2` 并保留 v1 过渡，不允许静默改语义。
4. 前端开发期用契约 mock（按 openapi.yaml 生成/手写 mock 数据）先行，不等后端；后端按契约实现并用契约测试校验响应结构。
5. 前后端联调只认契约：任何一边改接口需求，先改 yaml 并双方确认，再动代码。

## 3. 数据模型与接口

### 数据表（Sites 数据库）

| 实体 | 关键字段 | 说明 |
|---|---|---|
| User | id, auth_subject, created_at | 可空；游客用会话标识 |
| Asset | id, owner, kind(original\|result\|reference), storage_key, visibility, width, height | original 默认 private |
| Template | id, slug, title, cover_asset, prompt, negative_prompt, default_model, tags, features, sort | 代码种子；tags/features 供相似检索 |
| Skill | id, owner, title, prompt, negative_prompt, model, template_id?, tags, meta_json, source | 可导出；tags 供相似检索 |

资产原则：发布只触及 result + Skill 元数据；original 公开需显式选择（一期不提供）。字段为二期画册/三期社区预留，不改语义。

## 4. 关键设计决策

### 4.1 ImageProvider 接口

```ts
interface ImageProvider {
  generate(input: { prompt, negativePrompt?, model, baseImage?: bytes|url, ratio }): Promise<JobResult>
  optimize(input: { image?: bytes|url, text?: string, count: 2|3|4 }): Promise<PromptCandidate[]>
  tags(input: { image?: bytes|url, text?: string }): Promise<string[]>   // 相似检索用特征标签
}
```

- `AgnesProvider`：一期唯一真实实现。`UserProvider`（用户自带 Key/模型）后期按同接口扩展，一期不做。
- `MockProvider`：返回预置样片与固定候选词，用于无 Key/限流时兜底演示。

### 4.2 出图链路（保护原图隐私）

Agnes 图生图 `extra_body.image` 支持 **base64 data URL** → 用户原图以 base64 直传 Agnes，**不落公网**，隐私闭环成立。Agnes 返回的结果 URL 是公开 COS 链接 → 服务端立即下载转存到 Sites 存储，前端只展示本站 URL。

### 4.3 视觉分析的隐私路径（M0 已实测定案）

**2026-11-17 实测：Agnes 视觉模型接受 data URL（03 §7 T1）**，手册「只收公网 URL」结论被推翻。因此：
- 用户底图/参考图进入视觉分析一律 **base64 直传，全程不落公网（定案，无需临时公开机制）**。
- 生成链路同样 base64 直传（§4.2）。
- 链接解析所得图片本身来自公开 CDN，直接以其 URL 送分析，不再转存。
- 临时公开对象方案仅作历史备选保留于 05 文档，一期不实现。

### 4.4 限流与 Key 池

- 10 个 Key（6 中国站 + 4 国际站）存 Sites Secret；按站点分组，**Key 与 Base URL 严格配对**。
- 服务端令牌桶限速：**实测单 key 短窗口 2–3 次即 429（远严于标称 20 RPM）→ 保守按 ≤3 RPM/key + 请求间隔 ≥10s 控制**；429 时冷却并轮换下一个 key；全池耗尽 → 排队或降级 Mock。
- 公开站点加每游客生成配额（如每日 N 次），防刷。

### 4.6 自动 prompt 优化（MVP 核心）

- 统一入口 `POST /api/v1/optimize`：图片走视觉理解（隐私机制按 §4.3，M0 定 base64 或临时公开），文字走文本扩写；都用 `agnes-3.0-flash`。
- 输出结构化 JSON：2–4 条候选，每条含 `{ summary_zh, prompt, negative_prompt?, style_tags[] }`；`summary_zh` 是普通用户判断用的中文一句话，解析缺失时用中文标签兜底。解析失败重试 1 次后降级给通用候选。
- 保留约束按画面内容条件化：有人物时用「人物不变」；无人像的风景/物品用「场景、物体、光线与背景不变，不添加人物」。
- 一次调用同时产出候选与特征标签（省 RPM）；标签用于 §4.7 相似检索。
- 文字入口无底图：生成走文生图；有底图走图生图。UI 明示两种模式。
- 创作台 ready 阶段允许补/换/移除底图；换图后若提示词未被手动修改，模板会在文生图示意词与图生图提示词之间自动切换。

### 4.7 相似检索 + 预览（MVP 核心，不引入向量库）

- 模板/Skills 入库时预打 `tags`（风格/场景/主体，如「夜景,人像,提亮」）与 `features` 描述，存 DB。
- 检索：optimize 产出的标签与库内 tags 做加权匹配（DB 查询 + 服务端打分排序），取 Top 3–5；可选再让 LLM 对候选排序。
- 预览：推荐卡片展示封面样片 + 一句话说明 + 匹配原因（重合标签），不再展示易误导的百分比；一键套用回填完整配方。
- 无匹配（得分低于阈值）→ 返回全部 5 个模板作兜底并标记 `recommendations_fallback`，不挡主路径；创作台另有手动模板选择器。
- Skills 推荐携带 `negative_prompt/model/ratio/cover_url/cover_private`；私有封面按会话头读取。保存 Skill 时记录用户选中的候选标签、`template_id` 与当前结果封面。
- 模板变体（如夜景「雨夜霓虹」、旅行「复古明信片」）作为图生图变体暴露；无底图时禁用变体并提示先加图。
- 一期库规模小（≥5 模板 + 用户 Skills），关键词匹配足够；向量检索留二期。

### 4.7.1 任务恢复与配额（用户可靠性）

- 生成任务创建后，前端把 `job_id/prompt/model/ratio/asset_id/created_at` 写入 localStorage；成功/失败/超时同步更新，24 小时后自动失效。
- 刷新或重新进入创作台时显示「上次生成」入口：成功可恢复修前修后结果，排队/执行中可继续轮询，失败可恢复参数重试；不会重复扣配额。
- 任务仍由 `GET /jobs/:id` 驱动执行；用户离开页面时不后台跑，但回到创作台可继续。完整后台执行器留后续。
- `GET /quota` 返回单会话/全站今日额度与剩余；创作台展示剩余次数，额度用尽时禁用生成。

### 4.8 链接解析器（扩展模块，尽力而为）

- 范围：**仅抖音单条图文帖**（分享短链 `v.douyin.com/xxx`）。视频帖、主页、批量一律不做。
- 链路：短链 HTTP 重定向 → 图文 note 页 → 解析页面 SSR 数据取图片 URL 与文案 → 图片下载为临时对象 → 进入 optimize 流程。
- **自研轻量实现，不复制拾影任何代码（GPL）**；拾影的浏览器辅助签名方案不适用于云函数，也不搬。
- 用后即焚：解析所得图片/文案仅存临时缓存（Job 生命周期内），不落 Asset 库、不进日志、不公开展示；产出只保留提炼后的 prompt。
- 降级：风控拦截/解析失败/视频链接 → 明确文案引导「手动上传图片或文字，视频请截帧」，主路径不受影响。
- 合规红线见 [05-注意事项 §7](05-注意事项.md)；M0 先做可行性 spike，不通则整个模块延后，不影响 MVP。

### 7.3 关键设计决策

1. **AssetLibrary 服务**：归档/打标/检索/配额独立成服务，复用一期 AssetStore；业务代码不直调存储 SDK。
2. **检索分层**：默认标签加权 + 关键词（DB 查询，零额外成本）；对话检索为可选增强（LLM 解析意图 → 标签/向量排序），无预算则关键词兜底，不阻塞验收。
3. **flipbook 集成（MIT）**：复用 `create-photo-flipbook-ui` 的 `assets/3d-book` 运行时与 ui-collections 模板，**保留版权声明**；图派把 Album 的 result 集喂给它生成静态画册页，产物可导出 zip 或部署 Sites 子路径。一期不引入，二期 spike 验证打包体积与静态部署形态。
4. **拾影桥接（GPL 隔离）**：深度链接导入由用户本机拾影承担；二期可评估浏览器前端调其 localhost HTTP API（独立进程通信，不构成 GPL 衍生）。**云函数与公开参赛站不依赖此路径**，不复制任何拾影代码。
5. **登录方案**：优先 Qoder 登录态；如需独立账号走应用认证（显式凭证转发 + 单一验证器）。契约层 `X-Session-Id` 不变，登录态在其上叠加归属，不改一期结构。
6. **存储配额与删除容错**：每用户张数/容量上限，超限可读提示 + 自主清理入口，明示是否收费；删除走**回收站软删（`deleted_at`，宽限期内仍 private 可恢复）→ 期满彻底删除**（含缩略图与画册引用），避免用户手滑不可逆。
7. **归档自动打标**：归档时继承一期 optimize 产出的 `style_tags`，可选 AI 补标，免用户手动打标导致检索废；标签是检索与推荐的地基。
8. **傻瓜式分享**：画册分享优先生成**只读 unlisted 链接**（`share_token` + 可选有效期，无需登录即可看，可撤回），普通用户零技术门槛发给朋友；zip/部署为进阶选项。分享与撤回都只触及 result。
9. **游客留存引导**：一期游客数据存会话/localStorage，易失；二期 UI 明示风险并引导尽早登录绑定或导出保存，迁移不丢已有 Skills。

### 8.2 数据模型增量

| 实体 | 关键字段 | 说明 |

### 8.3 关键设计决策

1. **发布管线（含用户控制权）**：默认 private；发布是显式动作 + 隐私确认（剥离 original）→ 审核 gate → public。发布时可选「允许他人 fork」开关，含真人人脸时谨慎提示；发布后可撤回（`withdrawn` 停止新 fork）。审核未过不公开。
2. **Fork 引擎（低门槛+署名）**：继承 `skill_snapshot`（prompt/params/model），fork 者用**自己的底图或纯文字**生成（无底图走文生图，降低参与门槛）；记录 `parent_work/parent_skill/depth/author_credit`，**原作者署名沿链保留**。**任何路径都不携带他人 original 像素**。
3. **审核与安全（含申诉）**：发布前 AI + 规则审核（NSFW/侵权/真人肖像）；举报 → 复核 → 下架真删公开副本；**被误判者可申诉 → 人工复核 → 恢复**。合规红线见 [05 §6](05-注意事项.md)。
4. **防滥用**：发布/评论/fork/社区生成全链路速率限制 + 配额；防刷不击穿主路径。
5. **发现与搜索**：瀑布流 + 标签 + 排序（最新/热门）；全文检索作品/配方/作者/标签。
6. **通知**：fork/评论/任务动态入队列，可达可关。
7. **数据可携带**：用户导出全部公开作品+配方；注销删除公开内容（真删）。
8. **效果优先的作品页**：大图 + 一键做同款为主视觉，完整配方折叠可展开——新手不读 prompt 也能参与，技术细节按需查看（即梦式心智）。
9. **评论治理**：作者可删除/折叠自己作品下的恶意评论（`hidden_by_author`），配合举报与速率限制，保护创作者不被网暴。
10. **撤回的细粒度语义**：撤回停止**新** fork；已 fork 作品保留但标注「来源已撤回」，署名不抹除——平衡创作者控制权与既有共创链的稳定。

## 9. 二三期总体路线、依赖、成本与协议

### 9.1 依赖链

一期（创作闭环 + 资产钩子）→ 二期（账号 + 资产库 + 画册）→ 三期（社区 + 共创）。三期强依赖二期账号与资产库；二期强依赖一期 `kind/visibility` 钩子与 AssetStore。逐期交付，不跨期写业务代码。

### 9.2 成本演进

- 一期：只用 Agnes 免费服务（已拍板）。
- 二期：对话检索为可选增强，优先免费额度/关键词兜底；画册渲染为静态产物，无持续模型成本。
- 三期：审核与社区生成可能放大成本 → 评估**用户自带模型（BYO）**与按量付费；引入任何付费服务前单独决策，不默认开启。

### 9.3 协议边界汇总

| 项目 | 协议 | 边界 |
|---|---|---|
| create-photo-flipbook-ui | MIT | 二期复用运行时/模板，保留版权声明 |
| gcui-art/album-ai | Apache-2.0 | 对话检索参考，保留 LICENSE/NOTICE |
| 拾影 Shiying | GPL-3.0 | 独立进程 + localhost 通信，**不复制代码进图派** |
| open-image-prompts | 代码 MIT / 数据另议 | 只用风格卡结构，提示词重写，不搬源图 |

### 9.4 与一期契约治理的关系

二三期所有新端点先改 `openapi.yaml` 双方确认再实现；只增不改一期语义，破坏性变更升 `/api/v2` 并保留 v1 过渡。前后端仍可各自独立修改、部署、回滚。

### 9.5 跨期兼容与体验范式延续

- **配方向后兼容**：一期导出的 `tupai-skill v1` 文件二三期仍可导入（字段只增不改语义）；一期旧作升级后可见、可再创作，升级不丢已有 Skills。
- **体验范式延续一期**：等待骨架 + 阶段文案、失败可读错误 + 重试、降级明确标注、移动单列、隐私默认 private——二三期所有新页面沿用同一套，不另起炉灶。
- **升级引导**：一期→二期→三期提供功能发现入口与数据迁移路径，旧用户不被甩下。

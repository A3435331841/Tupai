## 0. 诊断结论（为什么要重构，以及重构什么）

对 `代码仓库/web/` 与 `代码仓库/server/` 做了逐文件核查，结论与直觉不同，先纠正三点认知：

| 直觉 | 事实（带证据） |
|---|---|
| "创作台/资产库/社区功能没做完" | ❌ 功能完整甚至过剩。`Studio.tsx` 1137 行、5 阶段状态机、30+ state；社区有十几种社交/审核动作；画册含只读分享与撤回；配方双向导出。`api.ts` 49 个方法后端**全部有对应路由**。 |
| "现在是 shadcn 默认朴素样式" | ❌ 主题已是完整暖色设计系统（`globals.css:21-131` 赤陶主色 + 宋体 display + 径向渐变 + 多层阴影），首页已达设计稿水准。 |
| "后端 35/35 通过 = 完整" | ⚠️ 只对 `openapi.yaml` 登记的 13 条路径有效；实际路由 49 条，36 条零契约覆盖；`schema.sql` 只建 5 表，路由用了 13 表。 |

**真正的缺口是两处：**

1. **前端 = 结构骨架从未写进三页**。设计稿的关键元素在源码 grep **零命中**：步骤条「放入照片/理解画面/选择方向/生成作品」、「我的影像档案」、「废片，也有第二次机会」、组件「灵感模板」。页面级设计类 `site-hero / site-kicker / site-flow-* / font-display` 在 `pages/` 下**只有 Home.tsx 用**。三张空数据截图把这个结构性空白放大成"像没做完"。
2. **后端 = 数据层与契约层脱节**。`schema.sql` 缺 8 张社区表 DDL（works/albums/likes/comments/notifications/tasks/submissions/reports/profiles）→ 新环境初始化后社区/画册直接 503；校验存在静默改写（`count` 非法吞成 3、`expires_hours` 非法吞成 7 天）；`openapi.yaml` 缺 36 条路径、错误码枚举漏 2 个、mock 与实现响应结构不一致。

**因此重构原则：前端只补结构与视觉编排（业务逻辑一行不动）；后端只补数据定义、集中校验与契约（路由语义不变）。**

### 2.2 P1 校验层：新增 `server/validate.mjs`

集中提供失败即抛 4xx 的校验原语，替换"静默改写"：

```js
str(field,{max,required,min})   // 字符串：类型/长度/必填
intInRange(field,{min,max,fallback}) // 整数：严格解析，非法→400（不再静默）
oneOf(field, values)            // 枚举：kind/sort/ratio/aspect
idOf(field, prefix)             // ID 正则：a_/wk_/al_ 等
jsonObject(field)               // 对象且非数组
bool(field)
```

**用 `validate.mjs` 改造的具体位置（全部在 `routes.mjs`）：**

| 位置 | 现状 | 改为 |
|---|---|---|
| `:474-475` | `count` 非法静默=3 | 400 `invalid_input` |
| `:767` | `expires_hours` 非法静默=7天 | 400 |
| `:545` | `model` 缺省静默默认 | 400（对齐 `openapi.yaml:482` required） |
| `:606-613` | `validateSkill` 不校验 model 白名单/画幅/style_tags | 加 `model ∈ MODEL_WHITELIST`、`aspect ∈ RATIOS`、tags 元素为字符串 |
| `:370-375,:850` | `kind/sort/limit/offset` 宽松 | 白名单 + 严格整数解析 |
| `:434-439` | 只信 `file.type` | 加 magic-byte 与声明 MIME 一致性（`util.mjs:90-125` 扩展返回格式标识） |
| `:1056-1061` | 通知已读恒返回 ok | 加 `found` 判断，否则 404 |
| `:185-189` | `viewerKey` 不校验 session 格式 | 复用 `SESSION_RE` 强度 |
| `:680-705` | `links/parse` 无 session/限流、跟随重定向 | 补 session + 限流 + 重定向后二次校验 hostname（防 SSRF） |

## 4. 实施顺序与验收

**顺序**（每步可独立回退）：
1. 后端 P0：`schema-community.sql` → `routes.mjs` 注销补删/对象补偿
2. 后端 P1：`validate.mjs` → `routes.mjs` 校验替换 → `util.mjs`
3. 后端 P2：openapi → contract-test → mock 三文件
4. 前端组件：4 个纯展示组件
5. 前端三页：Studio → Library → Community（逐页改，逐页 build）
6. 截图验收 + `npm run build` + `node api/contract-test.mjs`

**验收门禁**：
- `npm run build`（tsc --noEmit + build）通过
- `node api/contract-test.mjs` 全绿，且断言数 > 35（证明覆盖面提升）
- `node dev/community-test.mjs` 全绿（社区逻辑未破坏）
- 三张设计稿关键元素在源码 grep 命中：步骤条文案 / 我的影像档案 / 废片，也有第二次机会
- `data-testid="current-summary"`、深链 4 参数、五阶段流转不回归

## 5. 风险与规避

| 风险 | 规避 |
|---|---|
| 重构 Studio 破坏 1137 行逻辑 | 只改 JSX 包裹与新增展示组件，`setStage`/API/pollJob 一行不动；逐页 build |
| 右侧栏改布局影响资产加载 | 保留 `mode` state 与 `api.assets()` 调用原样，只换容器 grid |
| 后端校验变严导致现有调用失败 | 优先在"非法输入"路径变严；合法请求行为不变；契约测试先补再改校验 |
| schema 补表与线上已有表冲突 | 用 `CREATE TABLE IF NOT EXISTS`，独立 `schema-community.sql`，不直接改线上 |
| 契约测试假失败掩盖问题 | 先删假断言再补真断言，让通过率反映真实覆盖 |

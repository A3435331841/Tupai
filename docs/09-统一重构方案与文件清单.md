## 0. 诊断结论（为什么要重构，以及重构什么）

对 `代码仓库/web/` 与 `代码仓库/server/` 做了逐文件核查，结论与直觉不同，先纠正三点认知：

| 直觉 | 事实（带证据） |
|---|---|
| "创作台/资产库/社区功能没做完" | ❌ 功能完整甚至过剩。`Studio.tsx` 1137 行、5 阶段状态机、30+ state；社区有十几种社交/审核动作；画册含只读分享与撤回；配方双向导出。`api.ts` 52 个方法后端**全部有对应路由**（2026-11-18 复核）。 |
| "现在是 shadcn 默认朴素样式" | ❌ 主题已是完整暖色设计系统（`globals.css:21-131` 赤陶主色 + 宋体 display + 径向渐变 + 多层阴影），首页已达设计稿水准。 |
| "后端 35/35 通过 = 完整" | ⚠️ 当时只对 `openapi.yaml` 登记的 13 条路径有效；实际路由 56 个分支、42 个零契约覆盖（**2026-11-18 已补齐全量契约，见 §2.3 与 `api/openapi.yaml`**）；`schema.sql` 当时只建 5 表，路由用了 13 表。 |

**真正的缺口是两处：**

1. **前端 = 结构骨架从未写进三页**。设计稿的关键元素在源码 grep **零命中**：步骤条「放入照片/理解画面/选择方向/生成作品」、「我的影像档案」、「废片，也有第二次机会」、组件「灵感模板」。页面级设计类 `site-hero / site-kicker / site-flow-* / font-display` 在 `pages/` 下**只有 Home.tsx 用**。三张空数据截图把这个结构性空白放大成"像没做完"。
2. **后端 = 数据层与契约层脱节**。`schema.sql` 缺 8 张社区表 DDL（works/albums/likes/comments/notifications/tasks/submissions/reports/profiles）→ 新环境初始化后社区/画册直接 503；校验存在静默改写（`count` 非法吞成 3、`expires_hours` 非法吞成 7 天）；`openapi.yaml` 缺 36 条路径、错误码枚举漏 2 个、mock 与实现响应结构不一致。

**因此重构原则：前端只补结构与视觉编排（业务逻辑一行不动）；后端只补数据定义、集中校验与契约（路由语义不变）。**

### 2.2 P1 校验层：新增 `server/validate.mjs`

集中提供失败即抛 4xx 的校验原语，替换"静默改写"：

oneOf(field, values)            // 枚举：kind/sort/ratio/aspect
idOf(field, prefix)             // ID 正则：a_/wk_/al_ 等
jsonObject(field)               // 对象且非数组
bool(field)

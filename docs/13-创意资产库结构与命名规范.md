## 0. 设计原则（为什么这样设计）

现有资产库的根问题不是"文件乱"，而是**三个维度被压进了目录位置和单个 `status` 字段**，导致：

1. `approved` / `archived` 两态装下了"选中设计、在用素材、被否方案、过程截图、重复副本"至少五类语义；
2. 用途 / 风格 / 场景 / 页面 / 主题五个分类维度想同时表达，目录树做不到（组合爆炸）；
3. "历史版本"与"未选中/放弃方案"混在同一个 `archived` 里，无法分辨。

因此本方案确立 **五条原则**：

| #  | 原则                | 含义                                                          |
| -- | ----------------- | ----------------------------------------------------------- |
| P1 | **物理目录只表达稳定正交维度** | 目录按"资产大类 → 状态 → 版本"三级组织；多维分类交给标签，不建目录                       |
| P2 | **状态显式三处同步**      | 每个设计资产的状态同时体现在「目录分区 + 清单 `status` 字段 + 版本说明」三处              |
| P3 | **历史与放弃分开**       | 被采纳后被取代 = 历史；从未选中或被否决 = 放弃；二者物理隔离                           |
| P4 | **留档不等于设计**       | 截图、裁切、重复副本是过程证据（留档），不是设计决策产物                                |
| P5 | **中文语义 + 英文标识双轨** | 目录/文件名用中文表达语义；`id`、`slug`、版本号、扩展名、运行时路径保留 ASCII 保证机器可读与引用稳定 |

根目录名沿用 `资产仓库/`（已是中文，且 26 条运行时映射均指向它），**仅重组内部结构**，避免大规模引用断裂。

## 2. 状态标识与生命周期（核心）

### 2.1 六态定义

| 中文状态 | 枚举值          | 语义         | 判定要点           |
| ---- | ------------ | ---------- | -------------- |
| 草稿   | `draft`      | 探索中、未成形    | 还在画，不参与决策      |
| 评审   | `review`     | 已成形、待拍板    | 候选池，等人决定       |
| 在用   | `approved`     | 当前采纳、生产可用  | 同一资产单元**唯一**   |
| 历史   | `superseded` | 曾采纳、后被新版取代 | **曾被选中过**      |
| 放弃   | `discarded`  | 未选中 / 被否决  | **从未选中或被否**    |
| 留档   | `archived`   | 过程证据、非设计决策 | 截图、裁切、重复副本、旧清单 |

**关键区分**（回应你最关心的分辨需求）：

- 历史 vs 放弃：`历史` 是"上过台的好设计"，`放弃` 是"没被看上的方案"。一个留在主线可回溯，一个进冷宫不干扰。
- 放弃 vs 留档：`放弃` 是有设计意图但被否的产物；`留档` 根本不是设计（截图、裁切、哈希重复的副本）。

### 2.2 状态机

```text
                 ┌──────── 采纳 ────────┐
                 ↓                      │
[草稿 draft] → [评审 review] → [在用 approved] → [历史 superseded]
     │                │                        │
     │ 放弃           │ 放弃                    │ 被新版本取代
     ↓                ↓                        ↓
            [放弃 discarded] ←──────────────────┘（可选：历史也可转放弃）

[过程证据] ──归集──→ [留档 archived]（旁路，不进入主状态机）
```

规则：

- `在用` 对同一资产单元**有且仅有一个**，由该单元的 `索引.md` 指向；
- `在用` 被新版本取代时，旧版转 `历史` 而非 `放弃`；
- 任意未采纳版本被否决 → `放弃`；
- 状态流转必须写入 `决策` 元数据（谁、何时、为何），不可静默改状态。

### 2.3 状态三处同步

每个设计资产单元，状态必须在三处一致：

1. **目录分区**：资产物理上位于 `在用/`、`草稿/`、`评审/`、`历史/`、`放弃/`、`留档/` 之一；
2. **清单字段**：`资产总清单.json` 中 `status` = 对应枚举值；
3. **版本说明**：版本目录内 `版本说明.md` 顶部写明状态与决策理由。

> 校验：三处不一致视为资产库错误，纳入 §10 校验门禁。

## 3. 版本管理方式

### 3.1 版本目录格式

```text
vNN-YYYYMMDD-<中文意图>
```

- `vNN`：两位序号，同一资产单元内单调递增，**永不复用、永不重排**；
- `YYYYMMDD`：该版本定稿日期；
- `<中文意图>`：简短中文说明设计方向，如 `显影暗房`、`杂志策展`、`浅色克制`。

示例：

```text
v01-20261117-杂志策展      # 历史：Codex 早期策展稿
v02-20261118-显影暗房      # 在用：用户选定的当前版本
v00-20261117-浅色克制      # 放弃：浅色主题未选方案（v00 表示未进入正式序列）
```

> `v00` 约定：专用于从未被采纳的方案，与主序列 `v01+` 区分，一眼可辨"这不是正式版本"。

### 3.2 当前指针

每个有版本的资产单元（如 `50-页面设计/首页/`）根目录放 `索引.md`，内容包含：

```markdown
# 首页 · 设计索引

> 当前在用：v02-20261118-显影暗房 · 更新 2026-11-18

| 版本 | 状态 | 目录 | 决策 |
|---|---|---|---|
| v02-20261118-显影暗房 | 在用 | 在用/v02-... | 用户选定 C 方案 |
| v01-20261117-杂志策展 | 历史 | 历史/v01-... | 被 v02 取代 |
| v00-20261117-浅色克制 | 放弃 | 放弃/v00-... | 未选中 |
```

当前版本**只由 `索引.md` 与 `status=approved` 表达**，禁止用改名 `final` / 复制 `current` 目录表达。

### 3.3 版本说明模板

每个版本目录内 `版本说明.md`：

```markdown
# manifest · <版本目录名>

- status: approved | superseded | discarded | ...
- 版本: v02
- 日期: 2026-11-18
- 关联页面: 首页
- 取代: v01-20261117-杂志策展        # 可选
- 被取代于: —                        # 可选
- 决策: 用户选定 C「显影暗房」，理由：显影交互最能表达核心功能

## 内容
| 文件 | 用途 |
|---|---|
| 设计稿/ | 高保真稿 |
| 预览-桌面.webp | 定稿预览 |
| 原型/index.html | 可交互原型（可选） |
```

## 4. 分类维度与标签体系

### 4.1 原则：正交维度用标签，不用目录

用途 / 风格 / 场景 / 页面 / 主题是**交叉正交**的：一张图可以同时是「用途:画廊展示 + 风格:胶片日常 + 场景:夜景 + 页面:首页 + 主题:废片新生」。用目录表达会导致组合爆炸，因此统一用**受控标签**。

### 4.2 六个标签维度

| 维度 | 键名   | 受控取值（示例，可扩展）                      |
| -- | ---- | --------------------------------- |
| 用途 | `用途` | 画廊展示、模板封面、主视觉、演示样片、回归测试、文档配图、社媒分享 |
| 风格 | `风格` | 胶片日常、杂志策展、显影暗房、清透人像、夜景提亮、旅行明信片    |
| 场景 | `场景` | 人像、夜景、聚餐、食物、宠物、风景、室内、街拍           |
| 页面 | `页面` | 首页、创作台、资产库、社区、隐私页、全局              |
| 主题 | `主题` | 废片新生、私密守护、显影、共创、秋日电影              |
| 合规 | `合规` | 含AI标识、无肖像风险、需署名、私有                |

### 4.3 标签语法

- 清单中存为带维度前缀的字符串数组，避免歧义：

```json
"标签": {
  "用途": ["画廊展示"],
  "风格": ["胶片日常", "显影暗房"],
  "场景": ["夜景", "街拍"],
  "页面": ["首页"],
  "主题": ["废片新生"],
  "合规": ["含AI标识", "无肖像风险"]
}
```

- 受控词表存 `90-元数据/标签词表.json`，新增取值必须登记（含中英对照与说明），禁止随手造词。
- 一个资产每维度可多值，但优先精确匹配：能用 `场景:夜景` 就不写 `场景:风景`。

### 4.4 检索方式

- **人**：各资产大类 `索引.md` 顶部提供"按维度检索"表，链接到具体资产；
- **机**：`资产总清单.json` 提供筛选数据源，可按 `标签.维度` 过滤；
- 组合检索示例：`用途=模板封面 AND 风格=胶片日常 AND 状态=approved`。

## 5. 元数据字段规范

### 5.1 通用字段（所有资产必备）

| 字段       | 类型     | 必填 | 说明                                                   |
| -------- | ------ | -- | ---------------------------------------------------- |
| `id`     | string | 是  | 稳定唯一标识；新建用英文 slug，历史条目保留迁移前的既定 id                     |
| `名称`     | string | 是  | 中文可读名                                                |
| `type`   | enum   | 是  | `image` / `vector`（实际落盘仅此两类）                          |
| `子类型`    | string | 否  | 如 标志、色彩、AI生成                                         |
| `path`   | string | 是  | 相对仓库根的路径（中文目录）                                       |
| `分区`     | enum   | 否  | 在用/草稿/评审/历史/放弃/留档                                     |
| `状态`     | enum   | 是  | draft/review/approved/superseded/discarded/archived    |
| `版本`     | string | 否  | `vNN` 或 null                                         |
| `origin` | enum   | 是  | ai-generated/licensed/original/derived/project-owned |
| `license` | string | 否  | 授权协议，如 Unsplash License、MIT、项目自有                     |
| `sha256` | string | 否  | 文件哈希，用于去重与溯源                                         |
| `bytes`  | number | 否  | 文件体积                                                 |
| `visibility` | enum | 是  | public / private                                     |
| `runtime_path` | string | 否  | `web/public/` 下路径，指向运行时副本                            |
| `used_by` | array  | 否  | 使用方文件，如源码路径                                          |
| `派生自`    | string | 否  | 源文件 path 或 URL（旧 `derivative_of`），派生图必填                |
| `重复自`    | string | 否  | 同源副本的源 path（旧 `duplicate_of`）                         |
| `取代`     | string | 否  | 本版本取代的旧 id                                           |
| `被取代于`   | string | 否  | 取代本版本的新 id                                           |
| `标签`     | object | 否  | 见 §4.3 六维标签                                          |
| `决策`     | object | 否  | `{结果, 日期, 决策人, 理由}`                                  |
| `repository_scope` | enum | 否 | `local-only`：仅本地保留、公开克隆可缺少的条目                       |
| `扩展字段`   | object | 否  | 预留：未来新增字段先放这里，成熟后提升为正式字段                             |

> 以上字段名与取值类型以 `90-元数据/字段规范.json` 和 `资产总清单.json` 实际落盘键为准（schema 2.0）。早期草案以中文名作权威字段名（`类型/路径/来源/可见性/被引用于/运行时路径`）及「类型 = 品牌/技能/提示词/图片/页面设计/模板」六类枚举的表述已废止；`创建日期`/`更新日期`/`责任人` 当前未落盘，批次日期以 `决策` 字段与 git 记录为准。

### 5.2 图片资产附加字段

| 字段        | 类型      | 说明                            |
| --------- | ------- | ----------------------------- |
| `尺寸`      | string  | 如 `864x1152`                  |
| `生成工具`    | string  | 如 `agnes-image-2.5-flash`、GPT |
| `提示词路径`   | string  | 对应提示词资产 id 或路径                |
| `授权来源URL` | string  | 授权图原始链接                       |
| `含AI标识`   | boolean | 是否满足 AI 标识合规                  |
| `肖像风险`    | enum    | 无 / 待核 / 有（AI 人像需关注）          |

### 5.3 设计版本附加字段

| 字段     | 类型      | 说明         |
| ------ | ------- | ---------- |
| `关联页面` | string  | 首页/创作台/…   |
| `当前指针` | boolean | 是否为该单元在用版本 |
| `取代链`  | array   | 完整版本演进顺序   |

## 6. 命名规则

| 对象      | 规则                        | 正例                       | 反例                  |
| ------- | ------------------------- | ------------------------ | ------------------- |
| 一级/二级目录 | 中文语义名                     | `品牌资产/标志/`、`图片资产/AI生成/`  | `brand/logo/`（旧）    |
| 状态目录    | 六态中文名                     | `在用/`、`历史/`、`放弃/`        | `final/`、`archive/` |
| 版本目录    | `vNN-YYYYMMDD-<中文意图>`     | `v02-20261118-显影暗房`      | `最终版/`、`new-new/`   |
| 资产文件    | `<语义名>-<版本?>-<变体?>.<ext>` | `首页主视觉-v02-显影暗房.webp`    | `IMG_2841.png`      |
| 标识 `id` | 新资产用英文 kebab-case；存量中文 id 迁移期保持原值（以清单为准） | `home-hero-v02` / `首页主视觉` | 新资产用中文 id |
| 标签      | `维度:值`                    | `风格:胶片日常`                | 裸词 `胶片`             |
| 运行时路径   | ASCII，保持不变                | `/home/hero-street.webp` | 中文运行时路径             |

**总则**：中文负责"人看得懂"，英文标识负责"机器与引用稳定"。文件改名后必须同步 ① 引用该文件的 HTML/源码 ② `运行时映射.json` 的 `source_path` ③ `资产总清单.json` 的 `路径`。`web/public/` 路径一律不动。

禁止命名：`最终版`、`新版`、`old`、`new`、`final`、`copy`、`new-new`、随机 hash、无意义时间戳。

│  ├─ 字体规范.md                    # 字体栈、回退策略、无内嵌文件说明

### 7.2 20-技能资产

## 8. 检索与长期维护

### 8.1 新增资产流程

```text
新素材
 → 算 sha256，查 资产总清单.json
   → 命中：复用，不重复落盘（必要时标 重复自）
   → 未命中：判定来源 → 落入对应大类 + 状态分区
      → 派生：派生加工/ + 必填 派生自
      → AI生成：AI生成/草稿/ + 填生成工具、提示词路径
 → 打标签（按 §4 受控词表）
 → 写清单条目（§5 字段，状态三处同步）
 → 若被代码引用：同步 web/public + 更新 运行时映射.json
 → 更新所属单元 索引.md
 → 跑校验（§10）
```

### 8.2 状态流转流程

```text
草稿 → 评审 → 在用：更新目录分区 + 清单 status + 决策字段 + 索引.md 当前指针
在用 → 历史：新版本上位时，旧版移入 历史/，填 被取代于
任意 → 放弃：移入 放弃/，决策字段写清否决理由
过程产物 → 留档：移入 留档/，标 archived，注明来源单元
```

### 8.3 长期维护规则

- 每批次改动后同步清单与索引，不得滞后（当前无 `更新日期` 字段，改动时间以 `决策` 与 git 记录为准）；
- 标签词表每季度复核，合并近义取值，废弃取值标注 `deprecated` 而非直接删；
- 版本号只增不减，`vNN` 不回收；
- 每半年做一次哈希去重审计，命中重复标 `重复自` 并考虑移入 `留档/`；
- 私有资产与公开资产物理隔离，`可见性=private` 的条目不得出现在公开索引。
